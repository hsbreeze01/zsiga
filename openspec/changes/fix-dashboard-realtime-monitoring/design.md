# Design: Fix Dashboard Realtime Monitoring

## Architecture Decision

All 4 fixes target a single file: `zsiga/metrics/dashboard.py`. The dashboard is a static HTML generator that reads data files and produces `site/dashboard.html`. No server-side runtime is introduced.

### Data Flow

```
data/daemon_state.json  ──read──► _render_daemon_status()  ──► HTML card row
data/learnings.jsonl    ──read──► _render_failure_diagnosis() ──► HTML panel
metrics/collector.py    ──call──► compute_rolling_rates() ──► _sparkline_html() ──► HTML trend cards
(none)                  ──emit──► <meta http-equiv="refresh"> + hint text
```

## Key Design Points

### P1: Daemon Status Card
- Add a `_render_daemon_status()` helper function in dashboard.py
- Read `data/daemon_state.json` via `Path("data/daemon_state.json").read_text()` + `json.loads`
- Gracefully handle `FileNotFoundError` and `json.JSONDecodeError`
- Return an HTML string with a card row containing: PID, Started At, Cycle, State badge, Processing info, Heartbeat
- Insert the returned HTML in `_render()` between the hero section and the metrics grid

### P2: Failure Diagnosis Panel
- Add a `_render_failure_diagnosis()` helper function
- Scan `openspec/changes/*/` directories for `proposal.md` or `outcome` files with reverted/failed status
- Read `data/learnings.jsonl` and match entries with `pipeline.fail.*` or `code.*` patterns to changes
- For each matched failure, check if `openspec/changes/{name}/diagnosis.md` exists and is non-empty
- Render as `<details>/<summary>` elements, limited to 10 most recent
- Insert in `_render()` between Phase Performance table and Resource Usage section

### P3: Sparkline Trends
- Import and call `compute_rolling_rates` from `metrics/collector` (already exists in the codebase)
- Call `_sparkline_html` (already exists) with the rolling rates data for the Success Trend card
- For Duration Trend, generate pure-CSS bar chart: each bar is a `<div>` with `height` set as percentage of max duration, colored green/red based on outcome
- Insert both cards into the Resource Usage area in `_render()`

### P4: Auto-Refresh
- Add `<meta http-equiv="refresh" content="60">` to the `<head>` section in the HTML template string within `_render()`
- Add a small hint line `<div class="meta" style="text-align:center">Auto-refresh: 60s</div>` at the top of `<body>`

## Frontend Note

All rendering is server-side HTML generation in Python (string interpolation). No client-side JS framework is involved. The `site/dashboard.html` is a static file. The auto-refresh uses standard HTML `<meta>` refresh — no JS required.

The `site/dashboard.html` file itself is **not edited directly**; it is regenerated by running `dashboard.py`. All template logic lives in `zsiga/metrics/dashboard.py`.
