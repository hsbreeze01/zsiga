# Spec: mobile-responsive-layout

## ADDED Requirements

### Requirement: Mobile viewport adaptation via @media query

The dashboard HTML (whether rendered from `site/dashboard.html` or generated by Python in `zsiga/metrics/dashboard.py`) SHALL include a `@media (max-width: 768px)` rule that adjusts layout for narrow viewports.

#### Scenario: Card grid collapses to single column on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** the `.grid` element SHALL display as a single-column layout (one card per row)

#### Scenario: Hero section stacks vertically on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** the `.hero` element SHALL use `flex-direction: column` so mascot and info stack vertically
- **And** spacing between hero children SHALL be reduced

#### Scenario: Table remains readable on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** `table` font-size SHALL be reduced (e.g. 0.75rem)
- **And** `th, td` padding SHALL be reduced

#### Scenario: Stage progress bar scrolls horizontally on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** the stage progress bar container (`.phase-progress` or equivalent) SHALL have `overflow-x: auto` to allow horizontal scrolling

#### Scenario: Body padding reduced on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** `body` padding SHALL be reduced (e.g. 1rem)

#### Scenario: Heading size reduced on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** `h1` font-size SHALL be reduced (e.g. 1.2rem)

#### Scenario: Card values remain readable on mobile
- **Given** the dashboard page is loaded in a viewport ≤768px wide
- **When** the CSS is applied
- **Then** `.card .value` font-size SHALL be reduced but remain legible (e.g. 1.4rem)

---

### Requirement: Style consistency between template and Python rendering

If the dashboard HTML is generated by Python code (`zsiga/metrics/dashboard.py`), the mobile `@media` rules MUST be present in the Python-rendered `<style>` block, not only in `site/dashboard.html`.

#### Scenario: Python-rendered dashboard includes mobile styles
- **Given** the dashboard HTML is produced by `zsiga/metrics/dashboard.py`
- **When** the generated HTML is inspected
- **Then** it SHALL contain a `<style>` block with a `@media (max-width: 768px)` rule
- **And** that rule SHALL include the grid, hero, table, body, and heading overrides described above
