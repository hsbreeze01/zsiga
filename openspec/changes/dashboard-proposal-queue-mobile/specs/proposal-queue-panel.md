# Spec: proposal-queue-panel

## ADDED Requirements

### Requirement: Unified Proposal Queue panel

The dashboard SHALL render a single Proposal Queue panel via Python (not client-side JavaScript). The panel SHALL contain exactly two sub-sections: "当前处理中 (Current)" and "排队中 (Queued)".

#### Scenario: Dashboard renders exactly one Proposal Queue panel
- **Given** the dashboard HTML is generated by Python rendering logic
- **When** the page is served
- **Then** there SHALL be exactly one container element for the Proposal Queue
- **And** it SHALL contain a "当前处理中" sub-section
- **And** it SHALL contain a "排队中" sub-section

---

### Requirement: Current processing sub-section reads daemon state

The "当前处理中" sub-section SHALL read `current_change`, `current_phase`, and `heartbeat` from `daemon_state.json` and display the currently processing proposal's details.

#### Scenario: A proposal is currently being processed
- **Given** `daemon_state.json` exists with `current_change` set to `"my-change"`, `current_phase` set to `"IMPLEMENT"`, and `heartbeat` set to a timestamp
- **When** the dashboard is rendered
- **Then** the "当前处理中" sub-section SHALL display the proposal name
- **And** SHALL display the current phase name
- **And** SHALL display the heartbeat timestamp as start time
- **And** SHALL render an 8-stage progress bar with stages `CLARIFY → ENRICH → IMPLEMENT → REVIEW → VERIFY → OPTIMIZE → REFLECT → DELIVER`
- **And** the current stage (`IMPLEMENT`) SHALL be visually highlighted
- **And** all completed stages (`CLARIFY`, `ENRICH`) SHALL be marked as completed (green)
- **And** all remaining stages SHALL be displayed as pending (grey)

#### Scenario: No proposal is currently being processed
- **Given** `daemon_state.json` exists with `current_change` set to `null` or empty string, or `daemon_state.json` does not exist
- **When** the dashboard is rendered
- **Then** the "当前处理中" sub-section SHALL display an idle indicator (e.g. "💤 Idle — 等待下一个 proposal")
- **And** SHALL NOT render any stage progress bar

---

### Requirement: Queued proposals sub-section scans change directory

The "排队中" sub-section SHALL scan `openspec/changes/` to discover pending proposals and list them with metadata extracted from each `proposal.md`.

#### Scenario: Multiple proposals are queued
- **Given** `openspec/changes/` contains subdirectories `change-a/` and `change-b/`, each with a `proposal.md`
- **And** `change-a/proposal.md` first `#` heading line reads `"# Proposal: Feature A"`
- **And** `daemon_state.json` has `current_change` set to a different value (neither `change-a` nor `change-b`)
- **When** the dashboard is rendered
- **Then** the "排队中" sub-section SHALL list both `change-a` and `change-b`
- **And** each entry SHALL display a sequential number (1, 2, ...)
- **And** each entry SHALL display the proposal name (directory or extracted title)
- **And** each entry SHALL display the first `#` heading from `proposal.md` as a one-line summary

#### Scenario: No proposals are queued
- **Given** `openspec/changes/` exists but contains no subdirectories (or only the currently processing one)
- **When** the dashboard is rendered
- **Then** the "排队中" sub-section SHALL display "Queue empty" or equivalent empty-state message

#### Scenario: Currently processing proposal excluded from queue list
- **Given** `openspec/changes/` contains `active-change/` and `pending-change/`
- **And** `daemon_state.json` has `current_change` set to `"active-change"`
- **When** the dashboard is rendered
- **Then** the "排队中" list SHALL contain `pending-change` only
- **And** SHALL NOT contain `active-change`

---

### Requirement: 8-stage progress bar rendering

The stage progress bar SHALL render exactly 8 stages in order: `CLARIFY`, `ENRICH`, `IMPLEMENT`, `REVIEW`, `VERIFY`, `OPTIMIZE`, `REFLECT`, `DELIVER`.

#### Scenario: Progress bar at middle stage
- **Given** `current_phase` is `"REVIEW"`
- **When** the progress bar is rendered
- **Then** `CLARIFY`, `ENRICH`, `IMPLEMENT` SHALL be styled as completed
- **And** `REVIEW` SHALL be styled as current/highlighted
- **And** `VERIFY`, `OPTIMIZE`, `REFLECT`, `DELIVER` SHALL be styled as pending

#### Scenario: Progress bar at first stage
- **Given** `current_phase` is `"CLARIFY"`
- **When** the progress bar is rendered
- **Then** `CLARIFY` SHALL be styled as current/highlighted
- **And** all remaining stages SHALL be styled as pending

#### Scenario: Progress bar at last stage
- **Given** `current_phase` is `"DELIVER"`
- **When** the progress bar is rendered
- **Then** `CLARIFY` through `REFLECT` SHALL be styled as completed
- **And** `DELIVER` SHALL be styled as current/highlighted
