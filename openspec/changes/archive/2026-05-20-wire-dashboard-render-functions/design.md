# Design: Dashboard Render Function Wiring

## Overview

Wire 4 already-implemented but un-called functions into the `_render()` main function in `dashboard.py`. This is a pure integration task — no new logic, no new files, no frontend template changes beyond what `_render()` already generates.

## Architecture Decisions

| Decision | Rationale |
|----------|-----------|
| Only modify `_render()` body | Proposal constraint — all logic exists, just needs calling |
| Import `compute_rolling_rates` at call site | Avoid top-level import cycle risk; function-level import is safe |
| Wrap each section call in try/except | Ensures dashboard generation never fails due to a missing section |
| Keep f-string concatenation pattern | Follows existing `_render()` style |

## Data Flow

```
_render() entry
  │
  ├─ (existing) metric cards, hero, etc.
  │
  ├─ NEW: daemon_section = _daemon_status_section()
  │         └─ reads data/daemon_state.json → HTML fragment
  │
  ├─ (existing) Phase Performance section
  │
  ├─ NEW: failure_section = _failure_diagnosis_section()
  │         └─ reads failed changes + learnings → HTML fragment
  │
  ├─ (existing) Resource Usage section
  │
  ├─ NEW: rates = compute_rolling_rates()
  │       sparkline = _sparkline_html(rates)
  │         └─ rolling rates → inline SVG
  │
  └─ return f-string with {daemon_section}, {failure_section}, {sparkline}
       └─ written to site/dashboard.html
```

## Files to Modify

| File | Change |
|------|--------|
| `zsiga/metrics/dashboard.py` | Modify `_render()` only: add 4 variable assignments + insert into return f-string |

## Files NOT Modified (Explicit)

- `zsiga/metrics/collector.py` — read-only, `compute_rolling_rates` already exists
- `site/dashboard.html` — generated output, regenerated by `generate_dashboard()`
- `data/daemon_state.json` — read-only
- Any test files — no new testable public API surface

## Error Handling Strategy

Each of the 3 section calls (`_daemon_status_section`, `_failure_diagnosis_section`, `_sparkline_html`) SHOULD be wrapped so a failure in one does not prevent the rest of the dashboard from rendering:

```python
try:
    daemon_section = _daemon_status_section()
except Exception:
    daemon_section = ""
```

This matches the resilient pattern expected of a monitoring dashboard.

## Frontend Note

All rendering is server-side HTML generation within Python f-strings. No JavaScript, no CSS changes needed. The `site/dashboard.html` is overwritten by `generate_dashboard()` — no manual HTML editing required.
