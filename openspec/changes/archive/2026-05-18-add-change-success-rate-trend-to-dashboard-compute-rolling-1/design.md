# Design: Change Success Rate Trend

## Architecture Decision

The success rate trend feature is **entirely server-side rendered**, consistent with the existing dashboard architecture. The dashboard is a static HTML file generated by `zsiga/metrics/dashboard.py` using Python f-string templates — there is no client-side JavaScript framework or API endpoint.

All computation and rendering happen in Python at dashboard generation time.

## Data Flow

```
data/zsiga.db (changes table)
  → db.load_all_changes()           # ordered by id ASC
  → collector.compute_rolling_rates()  # NEW: returns list[float]
  → dashboard._sparkline_html()       # NEW: maps rates → sparkline + trend classes
  → _render() embeds card in grid     # MODIFIED: adds sparkline card
  → writes site/dashboard.html
```

## New Functions

### `zsiga/metrics/collector.py`

**`compute_rolling_rates(changes, window=10)`**
- Input: `list[dict]` from `load_all_changes()` (already ordered by id ASC)
- For each index `i`, compute success rate of `changes[max(0, i-window+1) .. i]`
- If `i < window - 1`, use growing window from index 0
- Returns `list[float]` of percentages rounded to 1 decimal

### `zsiga/metrics/dashboard.py`

**`_sparkline_html(rates)`**
- Input: `list[float]` of rolling success rates
- Takes the last 20 data points
- Maps values linearly to Unicode block chars `▁▂▃▄▅▆▇█`
- Wraps each character in a `<span>`:
  - `class="trend-down"` if `rates[i] < rates[i-1]`
  - No class otherwise
- Returns HTML string for the sparkline card

**`_render()`** — MODIFIED
- Calls `compute_rolling_rates()` to get data
- Calls `_sparkline_html()` to get the rendered card
- Inserts the card after the "✅ Verify Rate" card in the grid

## CSS Addition

One new rule in the `<style>` block:

```css
.trend-down { color: #ef4444; }
```

## Edge Cases

- **Empty changes**: sparkline card shows "—" placeholder
- **All rates equal**: every sparkline char is `▄` (midpoint)
- **Single change**: one data point, no trend detection possible
- **Rate = 0.0 or 100.0**: maps to lowest/highest sparkline char correctly

## Why No Frontend JS

The existing dashboard is fully server-rendered static HTML. Adding a JS-based charting library would introduce a new dependency and break the zero-JS paradigm. The ASCII sparkline approach is lightweight, consistent with existing patterns, and requires no external assets.
