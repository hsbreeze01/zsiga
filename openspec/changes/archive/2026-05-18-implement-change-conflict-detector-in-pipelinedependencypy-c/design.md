# Design: Change Conflict Detector

## Architecture Decision

Create a new module `zsiga/pipeline/dependency.py` containing the `ChangeConflictDetector` class and supporting dataclasses. This follows the existing pipeline module pattern (e.g., `diagnoser.py`, `enricher.py`) — a self-contained module with dataclasses at the top and a main class with public methods.

No LLM calls are needed; all logic is deterministic and file-based.

## Data Models

```python
@dataclass
class ChangeInfo:
    id: str                           # change directory name
    target_files: set[str]            # file paths parsed from design.md
    change_dir: str                   # full path to change directory

@dataclass
class ConflictPair:
    change_ids: tuple[str, str]       # sorted pair of change IDs
    shared_files: list[str]           # files targeted by both changes
```

## Data Flow

```
changes_dir/
  └─ scan_changes() ─→ list[ChangeInfo]
       │                    │
       │    parse design.md │ extract target_files
       │                    │
       └────────────────────┘
                 │
       find_overlaps() ─→ list[ConflictPair]
                 │
       suggest_order() ─→ list[str] (ordered change IDs)
```

1. **scan_changes**: Lists subdirectories of `changes_dir` (excluding `archive/`), reads each `design.md`, extracts target file paths into `ChangeInfo`.
2. **find_overlaps**: Pairwise intersection of `target_files` sets; returns `ConflictPair` for each non-empty intersection.
3. **suggest_order**: Topological-ish sort — changes with fewer overlap edges first, tiebreaker by lexicographic change id.

## Target File Extraction Strategy

Parse `design.md` content for backtick-quoted paths matching common file extensions (`.py`, `.md`). A simple regex `\x60([^\x60]+\.(?:py|md))\x60` captures these. This is robust because design.md files generated by the enricher consistently use backtick formatting for file paths.

## Files to Add/Modify

- `zsiga/pipeline/dependency.py` — New module: dataclasses + `ChangeConflictDetector` class
- `tests/test_dependency.py` — New test file covering all scenarios from specs

## Integration Points

- The orchestrator's `run_cycle` method in `zsiga/pipeline/orchestrator.py` may optionally call `scan_changes` + `find_overlaps` before processing proposals, but that integration is **out of scope** for this change.
- Uses `zsiga.pipeline.utils.read_file` and `zsiga.pipeline.utils.dir_exists` for file I/O (following existing patterns).
- Uses `zsiga.transport.Transport` for remote project support, consistent with other pipeline modules.

## Key Design Choices

1. **No LLM dependency**: All methods are pure computation on file content — deterministic and fast.
2. **Transport-agnostic**: Accepts optional `Transport` parameter, same as all pipeline modules.
3. **Dataclass-heavy**: Following the `diagnoser.py` pattern with dataclasses for structured results.
4. **Empty-set tolerance**: Changes without `design.md` or without extractable file paths participate in scanning but never appear in conflict pairs.
